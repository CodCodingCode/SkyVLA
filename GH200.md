# Running SkyVLA on a GH200

Setup notes for an **NVIDIA GH200 (aarch64)** host. Everything here was established the
hard way on this machine; the traps are the point, not the install commands.

Verified configuration:

| | |
|---|---|
| Host | NVIDIA GH200 480GB, aarch64, Ubuntu 22.04.5 |
| Driver | 580.105.08 (Lambda repo), CUDA 12.8 |
| Isaac | Isaac Sim **5.1.0**, Isaac Lab **2.3.2**, `isaaclab_rl` 0.4.7, `rsl-rl-lib` **3.1.2** |
| Torch | 2.7.0+cu128, Python 3.11.15 |

> The README badges say Isaac Sim 4.5 / Isaac Lab 2.1 / Python 3.10 under conda envs named
> `isaac` and `habitat`. That layout does not exist here and nothing depends on it.

## 1. Two virtualenvs, no conda

No single interpreter can hold both stacks, because Isaac pins `numpy<2` and current
`gsplat` builds want a newer toolchain.

| venv | Python | holds | used for |
|---|---|---|---|
| `.venv311` | 3.11 | Isaac Sim, Isaac Lab, rsl_rl, torch | physics, training, eval, rendering |
| `.venv` | 3.10 | gsplat | Gaussian-map rendering only |

```bash
export OMNI_KIT_ACCEPT_EULA=YES
export PYTHONPATH=/home/ubuntu/SkyVLA
export LD_PRELOAD=/lib/aarch64-linux-gnu/libgomp.so.1
.venv311/bin/python skyvla_isaac/scripts/<script>.py
```

### LD_PRELOAD is mandatory on aarch64

Without it the interpreter aborts before reaching any repo code, with a message telling you
to preload `libgomp`. It is not optional and not a warning. Convenience wrapper:

```bash
isaacpy() { OMNI_KIT_ACCEPT_EULA=YES PYTHONPATH="$PWD" \
  LD_PRELOAD=/lib/aarch64-linux-gnu/libgomp.so.1 .venv311/bin/python "$@"; }
```

### Never write `conda activate` into a script

Four run scripts did. With no conda present, activation fails silently, `python` resolves to
`/usr/bin/python`, and the run dies on `ModuleNotFoundError: isaaclab`. Because the scripts
wrap training in a restart loop, the loop then retried **forever** — looking alive in tmux
while training nothing. Those scripts were deleted.

**Reading a restart loop:** a teardown segfault *after* real iterations is benign (below).
A loop reprinting `[restart-loop]` every 10 s with no iterations in between is an
import/environment failure and will never make progress.

## 2. Vulkan — the GH200 ships compute-only

RTX rendering fails out of the box:

```
[carb.graphics-vulkan.plugin] VkResult: ERROR_INCOMPATIBLE_DRIVER
vkCreateInstance failed. Vulkan 1.1 is not supported, or your driver requires an update.
```

This is **not** a GH200 limitation. The driver is installed as compute-only: CUDA works, but
there is no Vulkan loader, no ICD in `/usr/share/vulkan/icd.d/`, and no `libGLX_nvidia`. The
graphics userspace libraries simply aren't there.

```bash
sudo apt-get install libnvidia-gl-580-server libvulkan1 vulkan-tools
vulkaninfo --summary | grep -E "deviceName|driverName"
#   deviceName = NVIDIA GH200 480GB
#   driverName = NVIDIA
```

### Install the `-server` variant. Not `libnvidia-gl-580`.

This is the one command on this page that can take the machine down. The installed driver
family is `*-580-server` at `580.105.08`. Asking for the non-server package makes apt
**remove the running compute driver**:

```
$ apt-get install -s libnvidia-gl-580          # DO NOT RUN
Remv libnvidia-compute-580-server [580.105.08]   <-- CUDA userspace, in use
Remv nvidia-compute-utils-580-server [580.105.08]
Inst libnvidia-gl-580 (580.119.02 ...)           <-- different driver version
```

That kills every running CUDA process. The `-server` variant matches the installed version
exactly and installs with **zero removals**. Always dry-run first:

```bash
sudo apt-get install -s <pkg> | grep -E '^(Inst|Remv)'
```

## 3. Version traps in the Isaac stack

### rsl_rl 3.1.2 silently drops old observation normalizers

`isaaclab_rl` installs **rsl_rl 3.1.2**, downgrading from 5.x. The two versions store
observation normalization differently:

* **rsl_rl 5.x** wrote the running obs mean/std to a top-level `obs_norm_state_dict`.
* **rsl_rl 3.1.2** deprecated `empirical_normalization`, moved normalization inside the
  policy, and its `load()` reads only `model_state_dict`.

So a 5.x checkpoint loads **without error** while its normalizer is discarded, and the actor
is fed raw observations. Symptom: a known-good policy scores ~0% in every configuration.
`model_9250` measured 0% grasp in six different setups before this was found; with the
normalizer restored by hand it scores 82.7%, matching its recorded 87.4%.

`scripts/run_pipeline.py` shows the fix — read `obs_norm_state_dict` from the checkpoint and
apply `(obs - mean) / std` before the policy. Checkpoints written *by* 3.1.2 are unaffected.

**If an old checkpoint scores zero everywhere, suspect the loader before the policy.**

### Isaac Lab 2.3.2 changed the env API

`get_observations()` returns a bare TensorDict, not `(obs, extras)`, and `step()` may return
five values. Old call sites raise `ValueError: too many values to unpack`. Accept both:

```python
_r = env.get_observations()
obs = _r[0] if isinstance(_r, tuple) else _r

_s = env.step(act)
dones = (_s[2].bool() | _s[3].bool()) if len(_s) == 5 else _s[2].bool()
```

Observations are TensorDicts keyed `"policy"` — index `o["policy"]` before slicing.

### Do not install rerun-sdk into `.venv311`

It pulls numpy 2.x plus newer `psutil` / `typing_extensions` and breaks Isaac Sim's pins.
Running jobs survive (modules already imported) but any restart fails. Use a throwaway venv:

```bash
python3 -m venv /tmp/rrenv && /tmp/rrenv/bin/pip install rerun-sdk
/tmp/rrenv/bin/python skyvla_isaac/scripts/rrd_from_trace.py --trace trace.npz --out out.rrd
```

If it happens anyway: `pip install numpy==1.26.0 psutil==5.9.8 typing_extensions==4.12.2`.

### gsplat is missing from `.venv311`

`gs_isaac_demo.py` and `render_rollout_gs.py` import **both** `isaaclab` and `gsplat`, and no
interpreter here has both. They cannot run until `gsplat` is installed into `.venv311`.
`render_gs_cache.py` is the Isaac-free consumer and works under `.venv` today.

## 4. Shutdown segfault is harmless

Training finishes, prints its `*_OK` line, then dies in `simulation_app.close()`:

```
Fatal Python error: Segmentation fault
  File ".../simulation_app.py", line 838 in close
```

Intermittent — the same command exits 0 on some runs, 139 on others. It happens *after*
checkpoints are written, so nothing is lost. Render scripts call `os._exit(0)` after ffmpeg
to sidestep it; `app.close()` can otherwise hang and leave a zombie renderer holding ~5 GB
of GPU memory.

An older note in `CLAUDE.md` blamed Xid 43 on an A100 with a cu130/CUDA-12.8 mismatch. That
hardware and that mismatch are both gone; this is a different, benign failure.

## 5. Practical notes

**Rendering.** Boots RTX in ~75 s. `render_snatch.py` drives a policy live;
`render_trace.py` replays recorded poses, which is the only practical way to film a rare
success (the three-policy pipeline completes ~0.6% of episodes, so attaching a camera and
hoping the followed env wins is not viable).

**Long runs.** tmux, always, with a restart loop — see `run_snatch_carry.sh`. W&B is on by
default and falls back to TensorBoard with no credentials. TensorBoard binds `127.0.0.1`;
reach it with `ssh -L 6006:localhost:6006 <host>`.

**Disk.** 3.9 TB, ~2% used. `.venv311` alone is 19 GB, so snapshot the volume rather than
rebuilding if the instance is terminated. `logs/` is gitignored — curate anything worth
keeping into `skyvla_isaac/snatch/checkpoints/` (the one path exempt from the `*.pt` rule,
and LFS-tracked).

**Pushing.** `gh` is not installed by default: `sudo apt-get install gh && gh auth login`,
answering **yes** to "Authenticate Git with your GitHub credentials". Checkpoints go through
Git LFS — confirm `Uploading LFS objects: 100%` on the first push. This repo already carries
two checkpoints whose LFS objects were never uploaded and are gone for good.
